# 标定与实车迁移

## 用实测数据配置虚拟小车

在 Windows 运行 `scripts/calibrate.bat`。先关闭 Webots，使用「空白 CSV」创建测量表，填入实测值后点「拟合 CSV」。核对结果，可另存 JSON，或确认应用到当前小车。以后可打开不同档案切换配置，重启场景后生效。测量值和标定档案留在本机。

CSV 表头是 `kind,channel,input,measured`。电机、超声波和红外可录入多组测量；`t63` 与 `encoder` 各填一行。未测到的项目可以整组留空。

| kind | channel | input | measured |
| --- | --- | --- | --- |
| `motor` | `left` 或 `right` | PWM 占空比，0～1 | 同方向的稳定轮速，m/s |
| `sonar` | 超声波名称，如 `front` | 实际距离，mm | 实测读数，mm |
| `ir` | 红外序号，从 0 开始 | 黑底填 0，白底填 1 | 实测归一化读数，0～1；12 位 ADC 除以 4095 |
| `t63` | `both` | 0 | 从静止阶跃到目标速度后，达到稳态轮速 63.2% 的时间，秒 |
| `encoder` | `both` | 车轮转过的圈数 | 两相计数的正增量，按固件使用的四倍频计数 |

电机需同时测左、右两轮，各有 `PWM=0` 时的零速度、满占空比速度及至少另一档稳定非零轮速；安全允许时增加靠近起转的测点会更有用。速度可从编码器转数与轮周长算出。超声波每路至少测两个不同的真实距离，尽量覆盖常用区间。红外每路同时测黑、白。数据应使用同样的电源、负载和轮胎条件，避免混合空载与地面数据。

档案会拟合两侧电机的稳态满速和死区，以及超声波的比例与偏移；查看 `rms_m_s`、`rms_mm` 可了解拟合残差。红外保留实测黑、白端点，黑白电平可反向。编码器每圈计数与响应时间是已有字段，两侧共用同一参数。电机采用单条稳态线段与一阶速度响应，反向、制动、电压变化仍需实车测量，PID 参数也要上车验证。

## 在两种串口之间切换

`simulator/tools/uart_transport.py` 提供相同的 `read(size)` 和 `write(bytes)` 接口。电脑视觉程序保留自己的串口封包与解析，只替换串口连接时的参数。运行程序前，将该模块所在目录加入 Python 导入路径，或作为单文件模块放进自己的工程。仿真侧使用标准库；实体侧额外需要：

```powershell
.venv\Scripts\python.exe -m pip install pyserial
```

```python
from uart_transport import open_uart

with open_uart(simulator_port=8765) as uart:  # 也可选 serial_port="COM5", baudrate=115200
    received = uart.read(256)
    # 需要发送时，调用 uart.write(自己的协议字节)
```

仿真端口须与配置的本机视觉接口一致，发送前应开始执行固件。默认从连接后的新字节开始读取；只有仿真可用 `from_start=True` 读取当前可用历史。仿真收发仍以固件采样周期推进，HTTP 请求本身有超时。仿真重启后，下一次查询服务器的读取会抛出 `ConnectionError`，下一次读取从新会话的可用字节开始；若读取过慢，`dropped_bytes` 记录因仿真缓冲区溢出而跳过的字节数。实体侧为非阻塞读取，打开串口前应核对设备和波特率；连接时不会自动发送协议字节，部分硬件可能因串口控制线变化而复位。串口包边界、重传和超时策略由各队程序负责。
