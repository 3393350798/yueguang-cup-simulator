# 视觉到固件联测

把本队视觉程序实际生成的字节，按记录时间送进两次独立的 Renode 虚拟 STM32 运行。你可以追到哪一个采样周期首次出现了不同的回包或 PWM，及附近有无掉帧、重发旧帧或恢复。此工具无需启动 Webots，不会打开 COM 口、发送实车指令或烧录板卡。

## 开始前

1. 在项目中运行 `setup.bat` 和 `scripts/setup-firmware.bat`。在硬件配置中保存待观察的电机 PWM、方向和虚拟 USART 设置；仅比串口时可以不绑电机。参考 [固件执行](固件执行.md) 和 [STM32 外设测试台](固件测试台.md)。
2. 准备 **同一套引脚和外设配置** 下的两份 STM32F103C8T6 镜像（ELF／AXF／HEX／BIN）。联测只替换镜像；两次使用相同 USART、CPU 指令率、引脚映射和传感器条件。红外原始输入用 0，数字电平按同一阈值换算；编码器不动，超声波无回波。BIN 的地址由共同的固件配置决定。
3. 双击 `scripts/vision-firmware.bat`，选「采集并对照」「导入串口 CSV 并对照」或「仅采集」。默认把文件放在本项目 `output/vision-firmware-*/` 下。提示选择镜像时，先选基线 A，再选候选 B。

## 电脑视觉：从固定帧采集实际输出

自己准备一个小的 Python 适配脚本，定义 `on_slot(image_bgr, metadata)`，把画面交给队伍自己的识别及协议封包。由平时写串口的那一步改成 **返回** 准备发送的 `bytes`，本时隙不发则返回 `None` 或 `b''`。每次最多 256 字节。脚本的同级目录可用于导入本队模块。适配脚本是本机执行的可信代码，**没有沙箱**；只选自己确认过的脚本，保证它不访问相机、实体串口或其它外设，尤其不要在导入模块时打开原控制链路。项目不提供识别或控制算法。

| 传给适配脚本 | 内容 |
| --- | --- |
| `image_bgr` | 正常、恢复或重发旧帧时，为 OpenCV 320×240 的 BGR 数组；掉帧时为 `None`。掉帧仍有时隙回调，可用自己的逻辑检查超时是否还会输出字节。 |
| `metadata` | `slot`、`scheduled_ms`、`state`、`sample_id`、`source_slot`、`captured_ms`。旧帧保留原源时隙和图像时间；掉帧没有源时隙、图像标识和图像时间。可用计划时间测试程序自己的时间逻辑。 |

该调用复用[连续帧回放](视觉连续帧回放.md)的正常轮和故障轮，默认故障轮。默认尽快运行，返回的字节记在该时隙的计划时刻；`--paced` 按约 250 ms 节拍调用，保存的依然是**计划时刻**。它不测相机曝光、识别耗时、实际串口写入时间或 USB 延迟。如要按实际写出时刻测试，请用队伍自己的电脑日志导出下节的 CSV。如果会员程序依赖实时定时器，并且需要比 250 ms 更密的事件，以团队记录为准。

```powershell
.\scripts\vision-firmware.bat run --adapter '队伍视觉适配.py' --mode fault --baseline '上一个版本.elf' --candidate '当前版本.elf'
.\scripts\vision-firmware.bat capture --adapter '队伍视觉适配.py' --mode baseline --out 'output\正常轮.csv'
```

## OpenMV 或已有电脑日志：导入本队串口时间表

已有 OpenMV 或电脑程序的日志时，可导出 UTF-8 CSV。`time_ms` 是**同一个记录端时钟**的相对毫秒，从你选定的测试起点算起；`hex` 是实际写出的字节（`00` 表示一个零字节，空字段才表示无发送）。一条记录一行，时间单调不减，相同时间按 CSV 原顺序保留、不会去重。可加 `slot`、`source_slot`、`state`、`sample_id`、`captured_ms` 标记；缺少的字段可以留空，`captured_ms` 只有同一个时钟时才填写。OpenMV 不需要安装本工具；这里只导入它已生成的记录，不运行 OpenMV 固件。

下面是格式示例，`10`、`00` 仅为占位字节，换成自己的数据；若没有时隙标记，只保留头两列即可：

```csv
time_ms,hex,slot,source_slot,state
0,10 00,0,0,normal
250,,1,,drop
500,10 00,2,2,recover
```

```powershell
.\scripts\vision-firmware.bat compare --trace 'OpenMV 发送记录.csv' --source openmv --baseline '上一个版本.elf' --candidate '当前版本.elf'
```

## 读报告

- 默认预热 128 ms，步长 32 ms，最后一条记录归入的周期后继续观察 256 ms。记录在 0 ms 或正好落在周期边界时，会在该周期开始前入队；其它时刻向后对齐到下一边界，例如 32.001 ms 归到 64 ms。每个周期入队的字节保持原序，周期末才取样回包和电机状态。它不重建串口逐字节物理间隔、串口包边界或真实无线延迟。
- `report.json` 分别记录全程和回放开始后的最早差异，也列出每个通道自己的第一个差异。它附最近的时隙、原始记录时间、入队位置以及周期末的采样时间，帮助定位，但不自动断定某一帧造成了变化。比较的是每个周期 MCU 发出的实际字节，即使长度相同也会给出这个周期首个不同或缺失的字节序号（从 1 开始，不含字节原文）。`0` PWM 表示确实观察到零；`null` 表示未绑定、不是输出模式或此 PWM 映射尚不支持。两边都没观察到时不会说电机工作正常。
- `--step-ms` 支持 8、16、32，`--warmup-ms` 和 `--tail-ms` 均用步长的倍数；超过 12 秒的记录请截成有代表性的片段。紧密轮询等固件的运行可能明显慢于真实时间；若电脑等待超时，可缩短记录或调高 `--timeout-s`（每版默认 180 秒，范围 10～600 秒）。退出码 0 表示在本次采样中未见差异，2 表示观察到差异，1 表示测试未完成。没有观察到差异不证明程序正确或实车安全通过。
- `input.csv` 可能含本队的**原始协议字节**，只在本机留存。默认报告含镜像 SHA-256、时间、字节数、引脚状态及差异点，没有镜像、路径或报文原文。文件不覆盖，也不会自动上传。需要求助时请先检查报告和选填标识，避免把原始记录、算法或固件发到公开仓库。
