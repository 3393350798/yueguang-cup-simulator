# 赛场容差回归

用同一套会员程序或固件，检查偏离标准摆位或照明条件后，最先卡在哪个赛段。所有偏差都是**仿真练习预设，未采用现场测量值**，也不作为正式赛场允许误差或计分依据。

1. 启动 Webots，进入网页面板的「批量练习」，选择「会员算法」或「STM32 固件 · Renode」。
2. 选择赛段，填写组号、物块颜色和「每轮秒数」。在「赛场容差」点击「开始容差练习」。
3. 每轮重新摆位并等车体停稳后开跑。结束后查看独立的容差通过率和每个预设的首个未通过项。中途可点「停止容差练习」或「暂停 / 停车」，已完成轮次仍能导出。

| 顺序 | 每轮只变一项 |
| --- | --- |
| 基准 | 当前赛段标准摆位和工程设定的灯光 |
| 起步左偏、右偏 | 小车分别沿自身横向左、右移 10 mm，朝向不变 |
| 物块摆偏 | 物块分别沿赛场 Y 轴移 +8、−8 mm，从面板上看为向上、向下 |
| 灯光变化 | Webots 主光源的直射、环境光强度相对项目默认值乘 0.75、1.25；环境光最高为 1 |

全程及抓放跑 7 轮；通道和停车不跑物块偏移，共 5 轮。「轮数」只影响普通的同条件多轮。容差练习不使用固定工况的定时故障，原有奇偶×红黄蓝六轮可继续单独运行。组号、颜色、时长和顺序在本组开始时确定。先固定这些设置及车模再对照两次结果。工程自身的噪声、随机种子等设置继续生效；外接电脑程序仍需自行在每轮清除状态。

灯光在每轮结束时恢复工程设定；全组完成或主动停止后自动恢复常规摆位。若面板断开，它无法发送恢复指令；重新连接后可用「摆位」或「回到起点」回到正常位置。不同物理模型会有不同的自然停稳位置，因此报告同时保存预设和开跑前实际读到的车位、物块位置及光强，便于复查。测试只改变这一轮的仿真场景，不会改写车模、地图或项目配置。

「通过率」等于通过的有效轮数除以有效轮数。正常运行到设定时长为有效轮，按选中赛段的练习判据判断是否通过。例如通道要求完整通过且没有碰撞。程序异常、提前结束或缺少开跑观测记为无效，不计入分母；未开跑或取消时尚未完成的工况单独统计，没有有效轮时不报百分比。首个未通过项按抓放、通道、停车的顺序检查，并不表示最早发生故障的时刻。

在「练习结果」点击「导出结果」生成本地 JSON。`records` 保留每轮详细结果，其中 `suite: "tolerance"` 标识容差记录；`tolerance_report` 是最近一组容差练习的预设、有效通过率和每项结果，包含未完成工况。容差轮不混入普通多轮汇总和固定六轮历史差异比较。报告不会自动上传，不含会员程序、固件或图像。

### 对照两版会员程序或固件

1. 用旧方案跑一组容差练习，点击「导出结果」。保留这个历史 JSON。
2. 更新会员程序或更换固件镜像，沿用原来的仿真版本、车模、赛段、控制模式、组号、物块颜色及每轮秒数。在「练习结果」点击「导入旧报告对照」载入旧报告，运行新方案。
3. 在「容差工况对照」中查看同一预设的前后结果。表中标明通过变未通过、未通过变通过，以及两次都未通过时首个未通过项是否改变。新的导出结果也会附带这一对照的 `tolerance_comparison`。

对照按预设 ID 配对，并核对扰动数值、赛场和仿真配置指纹。指纹也会核对车模、传感器设置，及固件模式实际使用的 STM32 引脚设置；允许会员程序内容或固件镜像不同。实际开跑条件也需接近：车位和物块位置各最多差 0.5 mm、车体朝向最多差 0.5°、主光源直射和环境光强度各最多差 0.0001。这些阈值用于隔开物理停稳的微小波动及不同摆位，不是比赛容差。

未完成、运行异常、配置不同或缺少指纹的工况会列出排除原因。对照表中历史和当前的通过数使用同一批可比工况；即便某组提前停止，已完整运行且匹配的工况仍可以逐项对照。v0.12.0 的容差报告没有配置指纹，可以查看原结果，但需用新版重跑旧方案才能算差异。同版本下如还有串流、串口输入等外部条件，两次应采用相同输入；工具无法替你核对这些外部条件。
