# 视觉连续帧回放

用同一组公开视觉图像检查队伍程序在掉帧、反复收到旧帧和恢复时的表现。无需启动 Webots、接相机或连接串口。图像来自[视觉单帧样本](视觉样本回放.md)，是按时间表排出的测试素材，不是小车连续行驶的录像。

## 在电脑上播放

运行过 `setup.bat` 后，双击 `scripts/vision-sequence.bat`，在浏览器打开 `http://127.0.0.1:8767/`，点击“正常回放”或“故障回放”。服务只监听本机；结束后在命令窗口按 Ctrl+C。若端口被占用，在命令提示符运行 `scripts\vision-sequence.bat serve --port 8768`，并把下方端口换成 8768。

在自己的电脑视觉程序里，把支持 MJPEG 的视频输入地址临时换成下面之一。也可以用项目环境的 OpenCV 打开该地址，然后将读到的图像交给原有流程。每次新连接从 0 ms 开始，6 秒后结束；要复测，关闭后重新打开。先看正常轮，再看故障轮。测试识别和指令输出时，可先把动作写入自己的本地日志，避免发送到正在运行的实车。

| 模式 | 视频地址 | 完整时间表 |
| --- | --- | --- |
| 正常 | `http://127.0.0.1:8767/baseline.mjpg` | `/baseline.csv` |
| 故障 | `http://127.0.0.1:8767/fault.mjpg` | `/fault.csv` |

例如，用 OpenCV 确认能读到输入：

```python
import cv2

capture = cv2.VideoCapture("http://127.0.0.1:8767/fault.mjpg")
try:
    while capture.isOpened():
        ok, frame = capture.read()
        if not ok:
            break
        print(frame.shape)  # 接入自己的识别流程时，用自己的处理函数替代这行。
finally:
    capture.release()
```

## 读懂时间表和结果

全轮有 24 个计划时隙，间隔 250 ms，最后一个时隙是 5750 ms。正常轮在每个时隙发送一帧。故障轮的其他时隙与正常轮相同，仅做以下修改：

| 计划时刻 | 状态 | 之后怎样恢复 |
| --- | --- | --- |
| 1250、1500、1750 ms | `drop`：不发送帧 | 2000 ms 发送当时的新帧 |
| 3000、3250、3500、3750 ms | `hold`：重复发送 2750 ms 的画面 | 4000 ms 发送当时的新帧 |

CSV 一行是一个计划时隙，包括掉帧。`slot`、`scheduled_ms` 是本次分配的时隙和时间；`state` 为 `normal`、`drop`、`hold` 或 `recover`；`sample_id` 是图像样本名；`source_slot` 和 `captured_ms` 表示画面来自哪个时隙。掉帧后三列留空。旧画面重发时，发送时隙继续增加，画面的源时隙和采集时间保持不变。同一张原图也可能在不同测试时隙作为新帧使用，所以 `sample_id` 相同不足以判定旧帧。

如果需要把识别结果或指令精确对回某一帧，可以在自己的 MJPEG 客户端读取每个图像分段的 HTTP 标头。依次对应六列：`X-Replay-Slot`、`X-Replay-Time-Ms`、`X-Replay-State`、`X-Sample-ID`、`X-Source-Slot`、`X-Capture-Time-Ms`。OpenCV `VideoCapture.read()` 只用来读图像；要保留这些标头，可读 MJPEG 分段，或按下列离线方案重放。时间表和标头用例内时间，适合对照。电脑实际接收时间还会受调度和解码缓存影响，不用于评估现场网络时延。

## 离线复测和 OpenMV

在命令提示符使用以下任一方式导出。每次填写一个新目录，已有目录不会被覆盖。

```bat
scripts\vision-sequence.bat export output\vision-sequence-png
scripts\vision-sequence.bat export output\vision-sequence-openmv --format openmv
```

导出的两个 CSV 与本机视频的计划一致。电脑版使用原始 `.png`，OpenMV 版使用同名 `.bmp`。按 `scheduled_ms` 读取时间表：在 `drop` 行不给程序送图，但仍保留等待时长；在 `hold` 行仍送图，用 `sample_id` 取对应图片，保留旧的 `source_slot` 和 `captured_ms`。记录程序结果时，把时隙号、观察到的识别结果及是否生成指令写到本地，再比较两个 CSV 对应的时隙。只比较逻辑顺序时，可以直接用计划时间逐行运行；检查超时行为时，需要按实际经过时间调度。

OpenMV 侧可先按[单帧导入说明](视觉样本回放.md#导入-openmv)验证一张 BMP 能否加载，再按 CSV 用自己的代码逐帧读取。BMP 每张约 225 KiB，空间有限时只复制该轮需要的文件，并逐行读取。导出和电脑回放经过软件验证，板端时间调度、文件加载和手机串流仍需按实际装备验收。公开包提供输入和时间表，不包含识别或比赛控制算法。
