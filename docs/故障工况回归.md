# 故障工况回归

用同一组定时故障，对比两版会员程序或固件。测试只影响虚拟赛场与虚拟 STM32，不连接实体串口。

1. 在练习面板选择需要检查的赛段与「会员算法」或「STM32 固件」，展开「分赛段练习 → 多轮对照 → 定时故障」。建议先选单一赛段，缩短排查时间。
2. 勾选「超声波无回波」，或选择虚拟 UART 的「断流」「延迟」。填写开始秒、持续秒和追加延迟。窗口从本轮**开始运行**计时，不包含摆位和等待停稳。每个窗口至少持续 0.064 秒，且须完全落在「每轮秒数」内。
3. 按「固定工况（6 轮）」，等待偶数与奇数组各跑完红、黄、蓝，再点「导出结果」保存基线。两项都关闭时，仍可将正常六轮作为基线。旁边的「开始多轮」始终是原有的同条件重复，不使用定时故障。
4. 修改程序后，在**同赛段、同模式、同车模、同用时、同故障窗口**再跑六轮，用「对照历史」打开基线。面板比较各自最近一套完整六轮，显示每种工况的首个未通过项，突出「通过 → 未通过」。全程模式还列出单个赛段的退步或改善，即使全程结果都未通过。

| 故障 | 实际注入方式 |
| --- | --- |
| 超声波无回波 | 对所有已配置的虚拟超声波输入生效。会员 Python 的测距仍使用最大量程的数值，并附 `sensors['sonar_no_echo'] = True`；未注入时该字段不存在。在固件模式内，窗口中的新触发不安排回波脉冲；窗口开始前已安排的脉冲可正常结束。 |
| 虚拟 UART 断流 | 仅固件模式。窗口内本应交付给虚拟 STM32 的输入字节被丢弃，适用于面板、电脑程序和会员自带视觉程序发来的数据；不改变 STM32 发出的数据。 |
| 虚拟 UART 延迟 | 仅固件模式。对窗口内到达的输入追加 1～3000 ms，并保持字节顺序。延迟队列最多 64 KiB；队列满会计数丢弃，超过本轮结束时间的待送字节不会进入下一轮。 |

故障窗口包括开始时刻、不包括结束时刻，按实际控制周期生效。结果会记录首个受影响采样时刻、超声波采样周期数、UART 受影响字节数。若窗口内没有输入，UART 会标明「窗口内无输入」；如果程序在窗口之前就报错，窗口可显示「未执行」。固定工况记录的首个运行事件包含碰撞、掉块或程序异常发生的仿真时间和赛场坐标。首个未通过项来自练习判定；没有现场事件的超时不会编造一个发生坐标。

只有完整、条件一致的六轮才能计算变化。未跑完的组、旧版报告仍可查看。版本、车模、场地、板卡配置（固件镜像除外）、步长、时长或故障窗口不同，不能用来宣布程序退步。重新导入或替换车模资产、修改仿真配置后，先重启 Webots。对照只核对仿真加载的配置，不验证外接电脑程序的版本、输出时序或导入几何文件是否在原路径被覆盖。外部视觉程序请每轮自行清状态；定时故障可复现注入窗口，不会重放外部摄像头或串口输入。

结果保存到本地。练习判定不替代正式计分，也不能据此判断真实传感器或无线链路的可靠性。
