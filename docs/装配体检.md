# 导入车模后的装配体检

导入底盘或 URDF 装配、设置车轮和传感器位置后，双击软件目录下的 `scripts/assembly-check.bat`，点击「开始体检」。先运行过 `setup.bat`。工具检查当前工程中已保存的车模，在独立的 Webots 空场运行；练习场景和原配置不变。你也可以勾选「显示 Webots 场景」，观察单轮和夹爪动作。

| 检查 | 会看到什么 |
| --- | --- |
| 左右轮 | 一次只给一个轮低速正向指令。记录车体前后位移、偏航角和编码器原始增量。车前由模型的 X 正向定义，左轮单独向前应使车向右偏，右轮应使车向左偏。后移优先查正向符号；前移但偏航方向颠倒优先查左右轮绑定。没有位移时还要查轮胎接地和碰撞几何。 |
| 红外 | 车不动，分别读取均匀黑、白参考地面的原始值。对比不足时核对离地高度、传感器是否被零件挡住，以及模型的地面响应；对比不足本身不能区分这些原因。 |
| 相机 | 默认在距车体原点 250、350、550 mm 处，依次放置正前方、左偏 110 mm、右偏 110 mm 的 100 × 100 mm 洋红标靶，标靶中心离地 75 mm。夹爪打开，有升降则分别在低位和高位取图。报告记录每组可见像素、范围、画面贴边和夹爪位置反馈，并保存原图。 |
| 夹爪 | 低位开合，若配置了升降则再测高位开合和返回低位，对照各阶段目标与位置反馈。体检场景开启车内碰撞并记录高于地面的接触；能定位到夹爪相关连杆时标出，否则只记录发生接触的阶段。 |

「符合」只指当前体检项目达到参考条件。「需核对」表示看到了需要检查的现象；「未观测」表示未配置、缺少反馈或行程未完整走过。没有观察到车内接触，只覆盖本次动作及 Webots 能检测的碰撞体；只导入外观网格的车仍使用简化的底盘包围盒。体检不能替代 CAD 全行程检查、实物装配验收或抓取测试。要比较夹持力、滑落及抓取容错，请用[夹爪测试台](夹爪测试台.md)。

相机标靶贴边会标为「需核对」；标靶可见也可能只露出一部分，要打开对应原图判断。若夹爪未确认达到设定姿态，该姿态的相机体检标为「未观测」。中央看不见但两侧可见时，优先检查夹爪、支架和车壳；三处都看不到时，也应检查朝向和视场。结果只覆盖这些标靶位置和夹爪姿态，不能用于判定实际标签或物块的识别成功率。

**比较候选安装位。** 在「候选相机 X,Y,Z（mm）,俯角（°）」填入待测试的四项数值，例如 `20,0,138,22`。坐标相对车体原点：X 向前、Y 向左、Z 向上，正俯角朝地面；朝向、视场和分辨率沿用当前配置。工具将用同一份车模副本比较已保存与候选位置；前者做完整体检，后者只复测相机。候选位不会写回工程。确定采用后，在[硬件配置](导入自己的硬件.md)中保存自己的相机参数。

从 v0.11.0 起，发行包默认车采用上面的候选姿态。以 320 × 240 原图为例，在 350 mm 中央参考点，旧版低位和高位均未观测到标靶像素；新姿态分别观测到约 4,210 和 4,214 个像素。默认三档距离、三处标靶、两种夹爪高度均能观察到标靶且未贴边。用工程升级工具迁移已有工程时，仍会保留已有相机设置。

完成后点击「打开结果目录」查看 `camera-comparison.csv`、`report.json` 和 PNG 原图。文件保存在本地 `output/assembly-check-*/`，不会上传。工具只复制必要的车模数据，不执行队伍算法、不读取固件或接通串口。日志和相机图片可以包含队伍自定义车模信息，按需自行选取分享。

命令行也可运行，端口默认自动分配；已有窗口占用指定端口时会提示换一个。

```powershell
.\scripts\assembly-check.bat --target-mm 350
.\scripts\assembly-check.bat --distances "250,350,550" --camera-pose 20 0 138 22
.\scripts\assembly-check.bat --show --port 1261
```
