# 实车串口自检

实车串口自检独立运行，检查 Windows 与实际 COM 口的收发，不需要启动 Webots 或 Renode。手机串流加电脑视觉方案，可以用它检查电脑到 STM32 的 USB 或无线串口；若 OpenMV 和 STM32 直接相连，电脑看不到两块板之间的字节，需要用板端心跳或另接一个调试口观察。

1. 运行过项目的 `setup.bat` 后，在项目目录打开 PowerShell，安装可选串口依赖：

   ```powershell
   .\.venv\Scripts\python.exe -m pip install -r requirements\serial.txt
   ```

2. 双击 `scripts/check-serial.bat`。程序先列出 Windows 上识别的 COM 口，此时还未打开任何设备。直接回车只列举；要监听时选择明确的 COM 口、填写与板端一致的波特率，并核对数据位、校验位和停止位。默认只监听，不发送。打开口之前关闭已占用该口的串口助手或视觉程序；部分 USB 串口打开时可能改变控制线、使板卡复位。
3. 如需验证往返，选择配置测试帧。只输入自己定义、确认不会驱动电机或夹爪的查询帧；没有安全的测试帧时只监听。可选填一段不出现在发送帧里的预期响应，以免把回显判成应答。输入 `SAFE` 后工具才会发送一次。发送前清除接收缓冲区，随后等待新字节；不会自动重发。最长监听 30 秒，达到 200 万字节时提前结束计数。
4. 检查结束后双击 `scripts/export-diagnostics.bat`，向负责人提供 ZIP 和简短现象。诊断记录只有结果、串口参数、字节计数和首次收字延迟；不含串口号、设备信息、测试帧、回包原文或 Windows 报错原文。不自动上传。

| 检查结果 | 可以判断什么 |
| --- | --- |
| 找不到 COM 口 / 所选 COM 口不可用 | 先查连接、驱动、无线配对或重新插拔后更换的端口。 |
| 系统拒绝打开串口 | 检查其他程序是否占用，以及本机访问权限；此结果不能单独确认占用的原因。 |
| 只监听时没有收到字节 | 可能只是板端不主动发送；这不证明板子未启动。 |
| 测试帧已写入、没有回包 | Windows 串口接受了写入，但没有收到响应；还需查协议、供电、板端是否运行和真实链路。 |
| 收到字节但未匹配 | 检查波特率、协议和选用的测试响应，也可能收到了另一种异步消息。 |
| 匹配到预期字节序列 | 证明本机在这次检查中看到了匹配字节。应选能区分本地回显和板端回答的应答；这也不证明电机或外设正常。 |

例如，在命令行列举端口，或打开明确指定的端口监听：

```powershell
scripts\check-serial.bat --list
scripts\check-serial.bat --port COM4 --baud 115200 --duration-ms 5000
```

`COM4` 和 `115200` 须替换为实际设置。可用 `--test-frame` 在命令行交互输入并确认主动检查；报文只在提示时输入，不需要放在命令参数里。

需要排查烧录或上电启动时，请同时看烧录工具的连接／校验结果，以及复位后的板端心跳或调试器能否进入主程序。串口自检无需刷写固件，也无法直接读出这些状态。
