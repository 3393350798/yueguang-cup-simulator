# 导出故障诊断包

在 Windows 上先重现一次问题，然后双击 `scripts/export-diagnostics.bat`。脚本会在项目的 `output/` 下生成 `moonlight-diagnostics-日期-编号.zip`，并在资源管理器里选中它。即使 Python 没装好、Webots 没启动、浏览器面板打不开，也可以单独运行这个脚本。

把 ZIP 发给协会负责人时，附上一句「我做了什么、预期是什么、实际发生什么」。如果问题与固件有关，也请说明队伍用的是 OpenMV 还是手机串流＋电脑视觉。ZIP 不会自动发送。

| ZIP 中的内容 | 帮助排查 |
| --- | --- |
| 仿真版本、Windows 版本与架构、虚拟环境是否存在 | 确认用的是哪一版，是否需要重跑安装 |
| 最近的安装和启动事件 | 区分 Python、依赖安装、Webots 路径、端口占用、场景生成和面板加载错误 |
| 近期控制器事件 | 查明接到哪一步，故障发生在场景配置、会员程序还是 STM32 固件；可识别错误类别，部分会员程序错误会给行号 |
| 已识别的控制台错误提示（有输出时） | 辅助排查依赖下载、图形环境、Python 扩展和控制器启动问题 |

负责人打开压缩包中的 `diagnostics.json`。同一次启动的启动日志、Webots 提示和控制器事件使用同一个 `session` 编号。常见情况：

- `missing_python` / `unsupported_python`：安装支持的 Python，再运行 `setup.bat`；启动阶段出现 `missing_python` 也可能是项目虚拟环境尚未创建。
- `dependency_install_failed`：检查网络，查看有无下载失败或没有兼容依赖包的提示。
- `missing_webots` / `port_conflict` / `panel_timeout`：依次核对 Webots 路径、是否开了上一轮 Webots，以及面板是否正常启动。
- `error`：结合 `phase`、`error_class` 和可用的错误代号定位。若只看到 `panel_ready`、没有 `controller_ready`，说明网页响应了，但控制器可能尚未完成初始化。允许 Webots 再运行几秒后重新导出。
- `firmware_missing` / `renode_missing` / `motor_pins_missing`：分别检查 STM32 镜像、Renode 安装和左右轮驱动引脚。若 `phase` 是 `member_vision` 或 `member_step`，优先核对会员程序；`member_line` 是本地模板文件里的行号。

原始日志在本机 `output/logs/`。部分 Windows 版 Webots 不会把控制台输出传给启动脚本；这时可用安装、启动和控制器事件定位，详细报错可在 Webots 窗口查看。ZIP 只提取限定的事件字段和提示代号，不附原始控制台内容、个人路径、会员算法、固件文件、队伍配置、相机画面或串口数据。需要补充原始信息时，请先由队员自己查看并只提供相关片段。日志目录可在关闭程序后清理。

已关闭或换过项目目录时，要从**发生故障的那个项目目录**导出。命令行或自动检查可用：

```powershell
scripts\export-diagnostics.bat -NoPause
```

需要检查实际接线或视觉通信时，再按[启动自检与接入](启动自检.md)操作。诊断包记录的是安装、启动及运行行为，不能证明实体板卡或无线链路正常。
