# 实车录制与联调

双击 **scripts/telemetry-record.bat**。可以同时选择电脑、OpenMV、STM32 各一份 CSV，然后点「读取时间线」。预览会逐台显示能观察到的事件、相邻事件耗时、以及没有可靠配对的环节。还能导出单台设备的标准波形 CSV，给[实车与仿真波形对照](实车波形对照.md)使用。

建议按一个动作只录一小段，完成后关闭日志文件再导入。**每个文件独立计时：同一设备、同一时钟、同一次启动。** 不同设备即使动作编号相同也不会相减；表中的时间都从该文件第一行算起。没有观测或缺少日志，不能据此断定板子没启动或没有收到指令。所有文件在本机处理。

如果要沿着取帧、发送、板端接收和轮速响应逐项检查，按[两种真机链路的验收](真机验收.md)录制并运行验收工具。用于检查实际轮速的 `sample` 行需同时标注动作编号。

## 两种队伍怎么记录

| 接线 | 可以记录什么 |
| --- | --- |
| 手机串流 → 电脑 → 无线串口 → STM32 | 在电脑的事件发生位置记录 `frame_received`（电脑拿到一帧）、`vision_done`（视觉处理完成）、`command_sent`（电脑串口写入返回成功）、`reply_observed`（收到且能确认属于该次指令的板端回执）。各事件用同一个动作编号，均走电脑自己的时钟。没有回执约定时省略该步。相机端何时曝光、无线通道单程耗时和板端执行时刻不能从电脑日志直接确定。 |
| STM32 与实体 OpenMV 直连 | 用 OpenMV 自己已能导出的日志记录 `frame_received`（板端取得一帧）、`vision_done`、`command_sent`；STM32 若有单独日志则记录 `command_received` 和 `reply_sent`，也可附它测到的轮速等值。分别导入两份日志。电脑需要一个独立观测点，才能读取两块板之间的字节。 |

电脑程序可以把 **simulator/tools/telemetry_log.py** 单文件复制到自己的项目，把已观测的事件写入 CSV。模块不打开摄像头或串口，也不发送控制指令。比如在不同回调里分别调用：

```python
from telemetry_log import TelemetryLog

log = TelemetryLog('car-run.csv', signals=('speed_left_m_s',))
# 分别插在现有程序观测到这些事实的位置，三处共享同一个动作编号：
# log.event('frame_received', seq)
# log.event('vision_done', seq)
# log.event('command_sent', seq)
# 回执由自己的程序解析并确认与该动作关联后：
# log.event('reply_observed', seq)
# 如果电脑已收到现成的轮速遥测，可以另记：log.sample(speed_left_m_s=已读取的轮速)
# 录制结束后：log.close()
```

录制模块用电脑的单调时钟，尽量在事件附近调用；它不重放、不猜测回执，也不读取图像或串口负载。运动控制程序中如对时序敏感，先验证日志调用的开销。设备原始测量时刻与电脑收到该测量的时刻不是一回事。如果有板端时间戳，保留原值，导入时为它选独立来源。

标准 CSV 用 UTF-8、逗号分隔，包含时间列 **time_s**，可加 **event**、**case_id**，波形列名见[实车与仿真波形对照](实车波形对照.md)。同一个动作的阶段用同一个编号；编号在一份日志里不能循环复用。只填写字母、数字、短横、下划线（最多 48 位），没有动作编号仍可计入事件数，但不算分段耗时。事件重复或顺序错误会标出，不会随意选一条。事件之间若有缺项，其余相邻两项齐全时仍可比较；不会跳过缺项来补算耗时。

```csv
time_s,event,case_id,speed_left_m_s
0.000,frame_received,42,
0.015,vision_done,42,
0.019,command_sent,42,
0.021,sample,,0.04
0.046,reply_observed,42,
0.052,sample,,0.06
```

普通采样行用 **sample**，这类行如果该时刻全部信号缺测，仍会按缺测保留该行。纯事件行不自动当成波形采样。CSV 时间不能倒退（板端计时器回绕或二次启动时请先按单次运行拆分）；波形导出时同一时刻的不同信号可合为一行，同一通道发生数据冲突会报错。读取限制为每份 CSV 48 MiB / 120,000 行。波形时间零点与同一份时间线一致，至少需要两个采样时刻和一路有值。报告和波形只保存识别出的事件与数值；事件编号会随报告导出，建议用匿名序号。

## 映射已有队伍 CSV

在窗口点「保存映射模板」，用文本编辑器修改 JSON，然后把它选在**对应设备**右侧。下面表示：时间用板端毫秒，动作、编号分别读 **action**、**seq** 列，把原始事件 `got_image` 映射为 `frame_received`。PWM 百分数乘 0.01；轮速列已经是 m/s。只保留原表里有的列，不需要的 **event**、**case_id** 和映射项可删除。

```json
{
  "time": {"column": "tick_ms", "unit": "ms"},
  "event": "action",
  "case_id": "seq",
  "events": {
    "got_image": "frame_received",
    "done": "vision_done",
    "sent": "command_sent",
    "ack": "reply_observed"
  },
  "signals": {
    "pwm_left": {"column": "left_percent", "scale": 0.01},
    "speed_left_m_s": "left_speed"
  }
}
```

时间单位也可选 s/us/ns。信号取 **原值 × scale + offset**；未填倍率或偏移时分别为 1 和 0。映射只转换你指定的字段，不读取协议报文，也不自动识别二进制文件。CSV 记录可以没有波形列，此时只查看时间线。

## 可选：录制已存在的独立调试口

如果 STM32 或 OpenMV 有**专门用于输出文本日志、且没有被视觉程序或串口助手使用的 COM 口**，可以用命令行接收一小段记录。先跑 [实车串口自检](实车串口自检.md) 的仅列出端口功能来核对设备，并安装 **requirements/serial.txt**。不要打开控制链路正在使用的口；即使录制只接收，打开调试口时某些转接器仍可能改变 DTR/RTS 控制线并使板卡复位。录制工具不写串口、不切换到其他口、不重试。

工具只接受板端已经输出的单行文本数据：逗号分隔、ASCII、换行结尾、按指定列顺序，每格是数字、空值或以字母/下划线开头的短标记。首个换行前片段会舍弃，因为接入时可能在一行中间。最多录制 60 秒；有不合格行时会计数。保存文件开头多 **rx_time_s**，它只是电脑读到这一段字节的相对时刻。应优先用板端日志自带的采样时钟（下例为 **tick_ms**）；同一批字节里的多行可能有相同的电脑收取时刻。

```powershell
New-Item -ItemType Directory -Force -Path output
.\scripts\telemetry-record.bat capture-debug --port COM5 --baud 115200 --seconds 10 --columns 'tick_ms,action,seq,left_percent,left_speed' --independent-debug-port output\board.csv
.\scripts\telemetry-record.bat template output\telemetry-map.json
# 按自己的数据修改 telemetry-map.json 后，可由窗口读取，也可使用命令行：
.\scripts\telemetry-record.bat timeline --source pc output\car-run.csv - --source stm32 output\board.csv output\telemetry-map.json --report output\timeline.json
.\scripts\telemetry-record.bat normalize output\board.csv output\board-wave.csv --mapping output\telemetry-map.json
```
