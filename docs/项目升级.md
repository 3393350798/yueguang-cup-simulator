# 队伍项目升级

升级工具把队伍的配置和程序放入一份**独立的新版目录**。旧工程和新版底稿都保留。先从 GitHub 下载并解压干净的新版，然后从新版的 `launcher.bat` 选择「队伍工程 → 迁移旧队伍工程」，也可直接运行 `scripts/upgrade-project.bat`。需要 Python 3.11～3.13，升级时不会运行队伍代码、安装依赖或联网。

1. 保存并关闭正在使用的旧工程。选择它的项目根目录，支持 v0.4 起的旧根目录布局和后来的 `simulator/` 布局。队伍 ZIP 仍从 `scripts/team-project.bat` 恢复；已有恢复工程也可当作旧目录。
2. 选择一个已存在的上级目录并填写新工程名称，点击「预览迁移内容」。新目录必须不存在，且不能位于旧工程或新版底稿内。预览列出车模、引脚绑定数量、实际引用的模型／网表／固件和会复制的 Python 文件，并提示在当前环境里找不到的静态依赖。如果引用文件丢失，先回旧工程补齐。
3. 检查预览后点击「确认并生成新工程」。工具在上级目录暂存并校验，成功后才建立最终目录。若确认时预览内的文件被改动，将提示重新预览；不会覆盖已有目录。
4. 在新工程运行 `setup.bat` 和 `scripts/check-setup.bat`。需要运行 STM32 固件时重新选择本机的 Renode。新工程用新版赛场文件，首次运行 `start.bat` 时按迁移后的配置重新生成 Webots 场景。

迁移机器人、板卡、固件配置，保留配置所引用的导入资产，以及 `member_algorithm.py` 和同一控制器目录下新增的普通 Python 模块、包。系统自带脚本由新版提供。预览会列出控制器下与新版同名而跳过的旧文件，以及其他未迁移的文件；如果修改过系统脚本，请核对是否需要手动合并。其他目录的代码、模型原始工程、日志、Python 环境和第三方包不自动迁移。若队伍自建了 `requirements/member.txt`，该文件会保留，需自行核对并安装。静态检查无法判断动态导入、传递依赖或实车外设是否正常。

命令行也可先只看预览，再决定是否生成。在新项目目录用 PowerShell 运行，例如：

```powershell
.\scripts\upgrade-project.bat --source '..\上一版练习' --target '..\新版练习'
.\scripts\upgrade-project.bat --source '..\上一版练习' --target '..\新版练习' --apply
```

带 `--apply` 时仍会先显示预览，并等待输入 `YES` 确认。该流程只在本机完成。新目录会含队伍自己的程序和固件，不应发到公共仓库。
