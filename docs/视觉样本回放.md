# 视觉样本回放

运行过 setup.bat 后，双击 scripts/vision-replay.bat 打开查看器。离线使用，无需启动 Webots。样本位于 simulator/assets/vision_samples/，共 15 张 Webots R2025a 的 320 × 240 RGB 车载相机图像：5 张标签、6 张单物块、2 张同框、2 张无目标背景。图像保留 2000 mm 赛场地图、彩色地面目标圈和赛题物块外形。标签为 AprilTag 36h11 的 ID 0/1；物块为红、黄、蓝。图像覆盖不同距离、视角、光照，其中一张标签被局部遮挡。

## 检查电脑视觉程序

选择“保存空白结果”。让自己的电脑视觉程序读取固定 PNG，并按结果格式写入 UTF-8 JSON。每条结果用同名样本 ID 对齐；要评价标签就填 tag_id，要评价物块就填 block_color。颜色写 red、yellow、blue；字段缺失代表未测试这一项，null 代表程序报告没检出。工具只读取结果文件，在本机做比较，不执行队伍程序，也不需要提交源码或串口报文。选择“打开程序结果”即可逐张查看漏检、误报和错认，也可以另存 JSON 对照报告。

示例结果文件：

    {
      "schema": "moonlight-vision-results-v1",
      "dataset": "rules-2000-webots-r2025a-qvga-v1",
      "results": [
        {"id": "tag01", "tag_id": 0},
        {"id": "empty01", "block_color": null}
      ]
    }

也可以在命令提示符批量使用以下命令。运行前确保输出文件夹存在：

    scripts\vision-replay.bat list
    scripts\vision-replay.bat template output\vision-results.json
    scripts\vision-replay.bat compare output\vision-results.json --report output\vision-report.json

## 导入 OpenMV

点“导出 OpenMV”可生成无压缩 24 位 RGB BMP 和 frames.json 文件清单。各 BMP 约 225 KiB，整组约 3.3 MiB。空间有限时，用命令行只选需要的几张：

    scripts\vision-replay.bat export-openmv output\openmv-samples
    scripts\vision-replay.bat export-openmv output\tag-only --sample tag01 --sample tag02

把需要的 BMP 复制到板卡可读取的存储位置，按 [OpenMV 的 Image 构造函数说明](https://docs.openmv.io/latest/library/omv.image.Image.html) 逐张加载，再用自己的程序识别。将下面的相对路径换成板上实际位置；先试一张，确认固件版本、路径和 RAM。frames.json 提供文件名与样本 ID 的对应关系；电脑端查看器或发行包里的 manifest.json 提供场景真值。导出已在电脑端逐像素核对，板端加载仍需用自己的 OpenMV 验证。

    import image
    frame = image.Image("tag01.bmp", copy_to_fb=True)
    # 把 frame 交给自己已有的识别函数并记录输出。

条件栏的距离和角度描述相机相对取景点的水平位置；同框样本以标签和物块的中点为取景点。图像没有标注框，真值来自采集场景，仅在查看器的单独一栏显示。局部遮挡样本的真值表示场景里确实摆放了该标签；码图不完整时未读出 ID 属于预期的压力结果。

真实比赛的牌面和物块外观、相机差异、自动曝光及现场照明可能不同；这组样本用于快速发现程序改动导致的回归，不等于实车识别验收。公开包只给测试图像、标签和评价工具，不含识别策略或会员程序。
